## Immediate next safe work

Continue the bounded audit and use a test environment that can initialize owned PostgreSQL and Mongo _test stores without bypassing the configured sandbox. The current Phase B harness failed before application tests because initdb's shmget call returned Operation not permitted. This is an infrastructure limitation; no application result was obtained.

The current source/UI trace is recorded in `OMS_WMS_INITIAL_AUDIT_2026-10-09.md`: overview results drive local search, filtering, paging, selection, stock SKU choices and KPI counts; export builders consume products and balances but the current SQL path first loads all overview collections and tenant balances. Do not add limits or push filters down until a disposable PostgreSQL run proves snapshot/result parity, selection semantics, invalid-ID rejection, query plans and representative output limits. Define expected page/export sizes from approved workload rather than inventing capacity. Meanwhile continue source-level authorization and workflow tracing plus isolated tests that do not require blocked PostgreSQL initialization.

## Gates and release rule

- Do not proceed from the existing Phase B checkpoint into Phase C until the recorded D11 workload and recovery targets and the Phase B exit evidence are reviewed and authorized.
- Do not change Central Inventory mutation or add another inventory authority. Every physical stock change must remain an auditable PostgreSQL ledger operation under its approved workflow.
- Do not run configured-store migrations/tests when an isolated _test database is required. Do not weaken TLS, authentication, tenant checks or auditing to make tests pass.
- Keep actual provider writes, production operations and deployment behind explicit approval.
- Production readiness remains blocked until security, data integrity, tenant isolation, provider resilience, queue recovery, performance, disaster recovery, observability and deployment evidence are complete.
