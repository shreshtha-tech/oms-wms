# Production domain ownership contract

Status: **implementation boundary, not launch approval**. Source reviewed on 2026-10-08. This contract names one owner for each business fact so that new work does not create a second authority. A named owner does not imply that its lifecycle or provider integration is complete. The existing [ownership matrix](architecture/ownership-matrix.csv) and [Phase B preparation](architecture/PHASE_B_PREPARATION.md) retain the detailed D01–D12 decisions; D06 package/custody stages and D11 operating targets remain incomplete.

| Domain | Authoritative fact and store | Permitted command owner | External input / projections | Current gap |
|---|---|---|---|---|
| Physical inventory | PostgreSQL `ci_inventory_event`; `ci_inventory_balance` is a transaction-maintained read model | `inventory/ledger.js` through approved count, receipt, transfer, order and return commands | Mongo inventory views and provider quantities are not physical evidence | Real opening stock, location basis and full writer audit are unverified |
| Inventory reservation | PostgreSQL `ci_reservation` and reserved columns on `ci_inventory_balance` | `inventory/ledger.js`, invoked by validated order commands | Provider order revisions are inputs, not reservation authority | Cart holds and full package-aware consumption are incomplete |
| Order identity | PostgreSQL `ci_unified_order` and `ci_unified_order_line`, keyed by tenant, account and external order/line | `inventory/unified-orders.js` through authenticated provider intake | Mongo sale orders are historical/legacy; provider order IDs are external identities | Not every provider has a complete feed and recovery path |
| Shipment/package identity | **No complete authoritative package ledger exists**; `ci_dispatch_evidence` records selected deduction evidence, while `ci_order_line_state` records line state | Future PostgreSQL WMS package service after explicit D06 contract | Provider shipment status and legacy Mongo shipments are evidence/projection only | Split package, manifest, handover and exact line/quantity identity are missing; block unsupported partial deductions |
| Warehouse custody | **No complete authoritative pick/pack/handover state exists** | Future PostgreSQL WMS custody service after D06 | Legacy Mongo picklists, fulfillment and manifest screens cannot create physical truth | Scan, actor, carrier, package and handover proof are incomplete |
| Provider inventory observation | PostgreSQL `ci_stock_observation` and observed fields of `ci_channel_stock` | `inventory/stock-observations.js` and approved provider readback adapters | Provider quantity is an observation with source time and account/location identity | Provider ordering and readback coverage are uneven; observation never overwrites central balance |
| Provider command/publication | PostgreSQL `ci_outbox` is the durable intent and now stores a per-command mapping/source-event snapshot, expected quantity, Agon request fingerprint, sanitized provider response reference, acknowledgement, readback and reconciliation result; `ci_channel_stock.target_quantity` remains a read model | `inventory/ledger.js` enqueues; `inventory/workers.js` claims, sends, records and reconciles through adapters | Provider acknowledgement and independent readback remain distinct evidence | Local uncertainty recovery is tested with simulated providers; live provider semantics, configured mappings, hosted workers and operator resolution of persistent mismatches remain incomplete |
| Return case | PostgreSQL `ci_return_case` and `ci_return_receipt` | `inventory/unified-orders.js` records provider case; `inventory/return-service.js` approves physical receipt | Legacy Mongo returns are historical/commercial metadata | Full RMA transport and item custody are incomplete |
| QC decision | PostgreSQL `ci_return_case.qc_status` currently holds narrow return receipt approval; no complete disposition ledger | `inventory/return-service.js` for its existing approved receipt path | Provider return/refund status and Mongo QC metadata cannot restock | Good/damaged/hold/write-off policy and evidence remain incomplete |
| Refund state | **No unified financial refund authority exists in Central Inventory** | Provider/commercial refund owner must be named before automation | `ci_return_case.provider_status` is a provider observation; legacy Mongo refund data is separate | Refund must never trigger physical stock restoration without receipt/QC evidence |
| Notification state | PostgreSQL `ci_order_alert` and callback status, with `ci_order_alert_source` and team/recipient tables for routing | `inventory/order-alert-routing.js` and `inventory/whatsapp.js` | Meta message ID/accepted/sent/delivered/read callbacks are evidence, not order or stock authority | Live Meta, sender ownership and callback proof remain unverified |

## Enforcement rules for subsequent work

1. Every physical change must use the ledger event path in one PostgreSQL transaction. Imports, refunds, provider observations and Mongo records must not update `ci_inventory_balance` directly.
2. A provider account, order, shipment, SKU and location must be resolved within the tenant before a command acts. Missing or conflicting identity enters review; no guessed mapping is accepted.
3. Provider observation, publication intent, acknowledgement and independent readback are separate facts. A successful HTTP response alone does not establish reconciliation.
4. Refund, return authorization, physical receipt, QC disposition and restock are separate transitions. Only an approved physical receipt/disposition can create a restock ledger event.
5. WhatsApp failure or success cannot roll back or advance order, reservation or warehouse state. Callback progression is owned by the notification domain.
6. Until a domain has an authoritative operational schema and command service, its legacy UI or metadata route remains a read/projection path for that domain. Do not turn a status field into evidence of custody or stock movement.

This document records boundaries for implementation. It does not approve real opening stock, enable a provider, resolve D11, or certify any hosted lifecycle.
