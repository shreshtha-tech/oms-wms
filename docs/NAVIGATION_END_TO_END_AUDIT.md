# Navigation end-to-end audit

**Audit date:** 24 September 2026, with focused PO Enquiry, PO Revision, Generate Vouchers, and Other Masters verification added 30 September 2026. **Source:** rendered rail definition in `src/eretail/menuData.ts`, click behavior in `src/eretail/Shell.tsx`, route table in `src/App.tsx`, and Express handlers in `server.js`. The initial route sweep visited all 149 linked URLs and clicked all 24 unlinked flyout buttons with MongoDB unset; it proves route loading only. The later focused checks used a generated admin and disposable MongoDB/PostgreSQL databases. They do not establish configured-tenant behavior, deployed services, marketplace accounts, or exact eRetail parity.

**How to read statuses:** “Broken” means the rendered menu cannot navigate or the route redirects. “Partially working” means the route renders but the code establishes a concrete missing/incorrect business behavior or a simulated data source. “Unverifiable” means the screen rendered in this run, but its action/data path was not exercised or persistence was unavailable. “Working” is reserved for an end-to-end behavior proven here; no global menu item met that bar. All legacy Mongo handlers use the seeded in-memory fallback when `MONGODB_URI` is absent or fails (`api/mongo.js:2-8,76-88`), so their HTTP 200 responses are not proof of real persistent data.
