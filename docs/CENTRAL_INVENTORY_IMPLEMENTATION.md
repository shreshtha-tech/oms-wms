## Excel workspace and Shopify verification — 24 September 2026

Open `/app/central-inventory`, or choose **Central Inventory** from WMS. The dashboard also links directly to the workspace. Its collapsible **Inventory management** sidebar contains Stock overview, Record physical stock, Excel upload, Low-stock alerts, Channel connections and Ledger activity.

- **Excel upload:** accepts `.xlsx` up to 7 MB / 50,000 rows. Catalog mode accepts the supplied `Seller SKU ID` / `Stock` layout to create identities and source provenance without setting stock. Verified physical-count mode reads the template's `Physical counts` sheet, requires an exact existing Central Inventory SKU and warehouse/store, then commits the on-hand count through the ledger. Counts are units of the exact SKU, including pack SKUs; component conversion is not inferred.
- **Preview and commit:** reports new SKUs, proposed count changes, duplicate/invalid/formula rows and pack listings. Any row error blocks the entire commit. Counts commit through the ledger in one transaction; retries of the same preview are idempotent. A preview expires after 30 minutes and is rejected if any target balance has changed since preview. The original workbook remains untouched.
- **Excel/PDF downloads:** export selected SKUs, or all current search/filter matches. Excel includes catalog, central summary, location counts and source notes. PDF includes SKU/product quantities, thresholds and unverified workbook quantities. Neither export changes inventory. Uncounted is displayed as “Not counted,” not asserted as physical zero.
- **Stock and alerts:** physical entry has a searchable SKU dropdown, location and operation dropdowns, and an optional low-stock threshold saved with the count. Bulk rules are available in Low-stock alerts. Rules open only for counted physical stock strictly below the threshold, and clear after recovery. Dashboard metrics use the same PostgreSQL data and refresh after inventory actions / every 30 seconds.
- **Channel reference checks:** a separate read-only connector probe can inspect seller stock for integration verification. It does not appear as a dedicated workspace screen or change central stock. This Shopify probe used [InventoryLevel](https://shopify.dev/docs/api/admin-graphql/latest/objects/InventoryLevel).

Commands: `npm run inventory:shopify-stock-check`, `npm run test:central-inventory-files`, and `npm run test:central-inventory-ui` (the tests require an isolated `INVENTORY_DATABASE_URL` containing `test` or `contract`).

## Setup and operation

1. Provision a PostgreSQL database and set `INVENTORY_DATABASE_URL` in the private environment. Set `INVENTORY_CREDENTIAL_KEY` to a random 32-byte hex encryption key stored in a secret manager. Set `INVENTORY_ALLOWED_TENANT_ID` to the tenant that this single-admin installation may operate. Do not reuse the app's MongoDB URI.
2. Run `npm run inventory:migrate`. Migrations are additive and do not backfill other inventory tables.
3. For `thread-sutra-fq9pshmi.myshopify.com`, create and install a [Dev Dashboard app](https://shopify.dev/docs/apps/build/dev-dashboard/create-apps-using-dev-dashboard) with `read_products`, `read_inventory`, `write_inventory`, and `read_orders` scopes. Shopify's [client-credentials grant](https://shopify.dev/docs/apps/build/authentication-authorization/client-credentials-grant?lang=node) only works when the store is in the app owner's organization. Put `SHOPIFY_CLIENT_ID` and `SHOPIFY_CLIENT_SECRET` in the private environment, never in chat, command arguments, or logs. Set `INVENTORY_SHOPIFY_DOMAIN=thread-sutra-fq9pshmi.myshopify.com` and run `npm run inventory:shopify-connect`. It verifies the actual shop and granted scopes read-only, then saves encrypted credentials with the account **inactive**. If Shopify rejects the grant because app and store ownership differ, use a merchant-approved authorization-code installation; the current script does not implement that flow. Other channel accounts can use the private stdin interface `npm run inventory:register-account` after their access contract is verified.
4. With a connected Shopify account, run `npm run inventory:shopify-discover` to retrieve a read-only first page of real product variants, inventory item IDs, and locations. It flags truncated pages; do not treat one page as the full catalog. Import verified MasterSKU and Location rows, then approve `ci_channel_mapping` rows (including explicit Shopify inventory item/location IDs or Amazon seller SKU) and activate only approved accounts. There is deliberately no automatic fuzzy match or activation.
5. Run `npm run inventory:worker` as a managed, continuously restarted process. It processes the durable outbox and reads back active approved Shopify mappings every 15 minutes. The Render blueprint defines a separate background worker; it requires the same PostgreSQL URL, credential key and tenant ID as the web process. Run `npm run inventory:migrate` before starting it. `npm run inventory:reconcile` is a standalone diagnostic alternative, not required alongside the worker. For Amazon, set `AMAZON_SP_API_APPLICATION_ID` on the web service to enable seller authorization. For SQS order/stock notifications, configure a platform-approved queue and a separate managed process running `npm run inventory:amazon-sqs` with `AMAZON_INVENTORY_SQS_URL` and `AMAZON_INVENTORY_ACCOUNT_ID`. Limit the queue policy to Amazon's authorized notification source; the SQS process is not included in the default Render Blueprint.
6. Deploy the server at a public HTTPS address, then set Shopify webhook target to `/api/inventory-sync/shopify/webhook`; subscribe to `orders/create`, `orders/cancelled`, and `inventory_levels/update`. The connector includes the documented `webhookSubscriptionCreate` mutation, but subscriptions must be reviewed and provisioned against the actual installed app. The handler requires raw-body HMAC, active account, and a unique webhook ID.
7. `/api/inventory-sync/events` now returns HTTP 501. A caller-supplied ledger event lacks a verified business transition, actor authorization, and source contract. Use the approved Central Inventory count/adjustment, inbound receipt, transfer, order dispatch, or return receipt workflow for a physical movement. `/balances` and `/drift` provide readback; `/partner-stock-file` accepts an approved quick-commerce observation snapshot, not physical on-hand stock. A POS ingest route requires a separate verified contract before activation.

Programme stock does not enter physical/sellable central balances. Programme reports require an explicit confirmation that the file contains only that programme. ### Mobile team number verification

Every WhatsApp team number, including managers, must verify control of the saved number during enrollment. Saving a member requests a WhatsApp AUTHENTICATION template even when the separate operational-alert consent has not been recorded; an unverified existing row has a **Send OTP** control. The six-digit code is HMAC-hashed with the Meta app secret, expires after 10 minutes, can be requested once per minute and at most 10 times per rolling 24-hour window, and locks after five incorrect entries. Successful verification stamps `verified_at`; order and packing alert queue creation and the worker require both that stamp and explicit operational-alert consent. Historical pending alerts are cancelled once by migration `016_whatsapp_recipient_verification.sql`, so verifying a number does not release old notifications.

Meta must approve an AUTHENTICATION template with an OTP Copy Code button. In WhatsApp Manager, create an Authentication template with the Copy Code OTP button and a 10-minute expiry. Set its exact name and locale as `WHATSAPP_OTP_TEMPLATE` and `WHATSAPP_OTP_TEMPLATE_LANGUAGE` on both web and worker services; the same settings are declared in `render.yaml`. The sender still needs WhatsApp Cloud API credentials. A local Meta send/verification cannot be proven until those private credentials, the approved template, and a live HTTPS deployment exist. [Meta's official authentication template example](https://www.postman.com/meta/whatsapp-business-platform/request/6vkv46u/create-authentication-template-w-otp-copy-code-button).
