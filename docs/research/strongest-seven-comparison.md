# Strongest seven: engineering comparison and decision

Intensive comparison is scoped to the named code/tests and revision in each UP record, not entire product certification. Upstream execution NOT RUN. Full local comparison is in 11-comparative-analysis.md, ledger-and-state-comparison.md and return-workflow-comparison.md.

| Candidate | Demonstrated source mechanism and test scope | Tradeoff / compatibility | Decision |
|---|---|---|---|
| Saleor UP-001/013/021/024 | Ordered stock locks; insufficient allocation leaves no allocation; mutation permission/channel denial; linked return/refund/after-commit delivery trace | PostgreSQL concepts fit. Django framework does not. Commercial returns differ from physical restock; after-commit callback not atomic durable outbox | Learn locks/eligibility/authority, preserve local outbox and receipt identity; BSD root, no code copied |
| ERPNext UP-007 | Bin/SRE reservation gates, cancellation restores reservation; sorted item/warehouse processing gates; FIFO/repost/cancellation assertions | Rich valuation/backdated/serial/batch policy is larger than strict integer local ledger; framework/DB-specific behavior matters | Learn sorted gates and failure tests; defer valuation expansion without requirement; GPL patterns only |
| Odoo UP-002 | Quant identity includes lot/location/package/owner; move completion checks company, picked lines/backorders; serial return and reservation relocation assertions | Physical stock granularity is valuable; negative/fractional policy and ORM lock semantics differ | Use domain/test ideas for approved R-06; no wholesale schema/ORM transplant; LGPL and file notices |
| Medusa UP-003/014 | Provider-key locking around reservation and compensation; totals tests; normal versus damaged return receipt actions | TypeScript fits, workflow runtime is substantial. Toy lock test not full checkout guarantee; Enterprise RBAC/SSO license exclusions | Learn disposition and compensating steps, defer orchestrator; retain SQL atomicity and uncertainty |
| Vendure UP-004/017/022 | Batch variant IDs sorted and fresh row-lock reads; final-unit/absolute-adjustment/bulk-settlement tests; payment-order channel checks | TypeScript fits. Driver/configuration fallbacks and custom allocation strategy constrain proof; fixed waits in tests | Strongest specific reference for LOC-016 fix and R-02 barriers; GPL/VCL, no copied implementation |
| OpenBoxes UP-008/HIST-001 | Lot identity/expiry source and transactional inventory service; actual PR5943 removes executable template behavior and adds endpoint authority tests | Physical WMS useful; Groovy/EPL implementation not stack fit; full balance writer/recovery unproven | Learn physical dimensions and risky execution/authorization boundaries; no direct library adoption |
| pg-boss UP-005 | SQL job expiry/retry/backoff behavior and nonzero retry regression assertions | PostgreSQL/Node fits; adding second queue lifecycle still adds migration/operations costs | Existing queue remains. Reuse retry/lease test ideas; consider dependency only for measured unmet need; MIT |

Independent Zehelein outbox supplies same-client effect/completion and late-timeout tests (UP-019); it also silently ignores duplicate IDs and completes unknown-handler messages. Neither policy should replace local canonical conflict rejection and unknown-command holds. Camel/Graphile/Debezium provide competing recovery/CDC mechanisms, not an adoption vote. OTel/Trivy/Scorecard inform bounded telemetry and evidence of scanner coverage/failure, not production-readiness labels (UP-020/025/026).

Diminishing-value stopping decision: the major recommendations now have direct local evidence plus competing source/tests and clear compatibility limits. More product discovery will not decide local return permission, physical warehouse contract, account-specific quota or recovery objectives. Those require the implementation/owner gates in the roadmap. Failed metadata/tree/path access remains recorded rather than filled with invented source claims.
