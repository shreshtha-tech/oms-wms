# Stock evidence and state design: competing models

Sources/revisions/licenses: UP-001/002/004/007/013/015/024 and LOC-001/003/005/007/016 in evidence.json. All upstream tests below were read, NOT RUN. Compare business semantics before copying representations.

| Stock evidence model | Transaction and concurrency mechanism read | History/reversal semantics | Relevant assertions and limitation |
|---|---|---|---|
| ERPNext Stock Ledger Entry / Bin | stock/stock_ledger.py:make_sl_entries acquires sorted item/warehouse processing gates before stock entry creation and bin projection; PostgreSQL gates are conditional on framework capability; valuations/reposting operate on historical sequence | Cancellation marks original entries cancelled and reverses quantities; backdated valuation can repost. This is not a strictly immutable event-log model | test_stock_write_takes_sle_advisory_gate measures held advisory locks; injected cancellation during repost remains cancelled; FIFO precision rate assertion. Does not prove full voucher transaction or all races |
| Vendure StockMovement / StockLevel | stock-movement.service.ts:adjustProductVariantStock opens/joins transaction, uses fresh locked levels, derives delta, saves adjustment and changes stock in same transaction; same-location repeated inputs use updated local map | Movement subtypes distinguish allocation/release/sale/cancellation; entity stockLocation relation cascades on deletion. Do not infer permanent immutable archive from a readonly TypeScript type | concurrency test asserts two absolute writes end at12 or MariaDB-aborted15 and movement delta matches balance; bulk reversed-ID adjustment versus settlement asserts no deadlock. Fixed1s observation and supported driver scope constrain test proof |
| Odoo moves / quants | stock_move.py:_action_done skips done/cancelled, filters picked quantities, checks company, makes backorders and delegates sorted move lines; quant helper locks/updates by physical dimensions | Move/picking execution and current quants are operational stock evidence; reservation/location/lot/package/owner differ from financial valuation ledger | Quant tests preserve serial across return and allocation5/3 across relocation. move_line completion internals/ORM transaction not fully traced; cannot claim immutable ledger or globally race-free final-unit handling |
| Local ci_inventory_event / balance / reservation | ledger.js locks parent SKU then balance, validates canonical replay and integer/nonnegative invariants, commits event/balance/reservation/alert/outbox with caller transaction | Append-style event usage and exact identity conflicts are valuable; migration schema does not alone prove privileged DB users cannot alter history | Owned LOC-016 fixture verifies opposite-writer lock order deadlocks, rollback preserves stock, stable retry/replay works. Common ordering is necessary despite safe rollback |

R-02 decision: keep existing local event/balance/outbox authority. Pre-acquire all parent SKU locks in one consistent internal-ID order before executing any multi-SKU writer. Keep request normalization/digest order independent. Define negative-stock/UOM and historical valuation policy separately; ERPNext float valuation and Odoo physical quant semantics are not a reason to weaken the local integer ledger. Privileged database immutability/retention policy remains an operational control question (R-07/R-09).

## Order and fulfillment state mechanisms

| Mechanism | Guard and side effects read | Lesson / limit |
|---|---|---|
| Vendure command transition graph | default-order-process.ts defines allowed transitions and optional payment/fulfillment checks; transition end applies configured placement/allocation strategies, seller-order split and history | Policy/configuration changes behavior. State transition plus durable effects must be tested with actual strategy. Custom same-transition concurrency tests are not proof of every configuration |
| Saleor derived order status plus commercial fulfillment records | order/utils.py locks order before status recomputation from fulfilled/returned/awaiting-approval quantities; return action separates replacement, returned and refunded records | Derived status summarizes quantities; it does not grant operation permission or establish physical QC. Payment action has external boundary. See linked return trace |
| Tryton physical shipment workflow | stock.shipment.out.return graph includes draft→received→done and explicit cancel/reset paths; receive completes incoming moves and creates stow moves; do checks quantities and completes stow; employee attribution decorators | This is a physical custody state machine, not a substitute for payment/order state. Scenario asserts incoming done/storage draft after receive and all done after completion; ACL/crash behavior remains framework scope |
| Local provider observation + stock line state + physical return | Provider revisions and terminal line rules protect reservation/consume/release; provider-authority gates distinguish observation from dispatch; return restock bounded by dispatched units | Keep financial refund, provider status, physical custody, inventory reservation and QC disposition separate. Staff shortcut501 is truthful while physical evidence workflow is unavailable |

R-06 decision: add only reviewed physical command transitions with actor, warehouse, evidence identity, partial quantities and reversal/cancellation policy. Three approaches above are deliberately compared at different layers; none proves full enterprise OMS state coverage by itself. Do not create a generic status setter or import an orchestrator to hide missing domain rules.
