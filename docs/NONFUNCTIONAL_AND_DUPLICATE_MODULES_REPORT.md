# Nonfunctional and Duplicate Modules Report

Audit date: 30 September 2026. This report consolidates the requested module checklist, current menu/router/API source audit, isolated handler checks, and the historical 24 September local menu-click evidence. Signed-in isolated browser checks now cover selected workflows including Vendor, Client, Customer Group, Tax Category, Tax Code, Tax Group, Tax Zone, Tax Application, SKU Master, SKU Import, SKU Barcode, SKU Company Link, SKU Channel Listing, SKU Moderation, OMS Rules, Manage SKU Group, Merchandising Hierarchy, Manage Attribute, Attribute Set, Vendor SKU Catalog, Vendor SKU Loc Catalog, Manage Channels, ARS SKU-Location Link, ARS Rules, ARS Execution Log using a labeled read-only historical fixture, B2B ARS Settings, WMS Zone, Picker Zone Preference, Bin Create/Edit, Bin Enquiry, guarded BIN Audit, Cycle Count Wave, Allocation Strategies, PutAway Rule, PutAway Enquiry draft handling, Lottable Validation, and Receipt Validation; SKU Label Print is explicitly blocked until real rendering/output exists. These checks ran against generated local databases; the configured MongoDB URI still fails a read-only ping with `MongoServerSelectionError`. Provider feeds, most other route actions, production-tenant behavior, and live seller-channel behavior remain unverified. “Nonfunctional” describes the listed route/action as it is currently implemented; disabled menu entries cannot change application state.

COD Reconciliation was also checked in a signed-in generated MongoDB workflow. The visible search filters work against isolated legacy order rows; reconciliation, force, import, and export are now blocked until settlement evidence and report delivery exist. See [COD Reconciliation evidence](COD_RECONCILIATION_REPLICATION_EVIDENCE.md).
